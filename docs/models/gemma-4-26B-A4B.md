# gemma-4-26B-A4B

Gemma 4 26B A4B (Google/unsloth, Apache-2.0, MoE QAT VLM): 25.2B total / 3.8B active MoE (arch `gemma4`, 30 layers per the card but `n_layer 31` in the GGUF, 8 of 128 experts active + 1 shared, sliding window 1024, native 256K ctx). Same hybrid attention as the 31B, and the load log shows the consequence directly — `llama_kv_cache: layer 3: sharing with layer 29` — which is why the full native context is affordable. `UD-Q4_K_XL` (13.3 GB) plus the 252 MB drafter `mtp-gemma-4-26B-A4B-it.gguf`. **The drafter was the find**: the card documents `--spec-type draft-mtp --spec-draft-n-max 4`, but only the main GGUF had been downloaded and `models.list` carried a single line for this repo, so `recommend.sh` correctly reported "no MTP head found" and the section ran `ngram-mod` alone. Both are fixed. Measured on hermine 2026-08-05 by actually loading the server at `ctx-size = 262144`, KV `q8_0`/`q8_0`, draft KV `q4_0`/`q4_0`, `spec-draft-n-max = 4`: **21193 MiB peak of 23028** (~1835 MiB free), **8109 t/s prompt** (7828-token prompt), **234.6 t/s generation** (400 tokens), and MTP **draft acceptance 0.751** with mean draft length 3.99 — the budget of 4 is fully used, so it is not set too high. After a long prompt acceptance drops to 0.547 / mean 3.13 and generation to 158.6 t/s. Roughly 3× the 31B's prompt and 2–3× its generation throughput at 3.8B active parameters, and unlike the 31B it holds the full 262144 rather than 65536. Two caveats on those numbers: the runs where generation was exercised omitted `cache-reuse` and read 20766–20778 MiB, ~430 MiB below the load that included it — **unexplained**, and the higher figure is quoted because it matches the written section. And `llama-fit-params` alone had reported 18031 + 240 MiB, a lower bound, because it cannot size a separate drafter's context; only the real load settles it. Sampling is one single published set for all use cases — `temp 1.0`, `top-p 0.95`, `top-k 64` — already in the section. **Thinking must not be forced on here.** `recommend.sh` flagged that the template consumes `reasoning_content` from history and suggested `reasoning = on`, as with Laguna; the card says the opposite in so many words ("Thoughts from previous model turns must *not be added* before the next user turn begins") and makes thinking opt-in per request via a `<|think|>` token in the system prompt. So this is not the Laguna case, `reasoning = on` stays out, and `jinja = true` + `reasoning-format = auto` are enough. `cache-reuse = 256` is kept but is **inert**: the server logs `cache_reuse is not supported by this context, it will be disabled`. It is left in so it starts working if a future build supports it — the limitation turned out not to be architectural at all, see the dedicated bullet below. Text+Image per the card (~550M vision encoder), but no `mmproj-*.gguf` is present, so the preset is text-only.
