# Ornith-1.0-35B
> Extracted verbatim from AGENTS.md on 2026-08-15. "Above/below" references may point
> to sibling files in this directory or back to AGENTS.md.

Ornith-1.0-35B on hermine is the section that **disproved this repo's own ctx policy**, measured 2026-08-05 with eleven real loads. `Q4_K_M` is 20186 MiB on a 23028 MiB card, so the inherited `ctx-size = 262144` could not have loaded at all. With `fit = off` (full GPU residency) generation is **flat** at 158.5 / 157.9 / 157.4 t/s for ctx 32768 / 65536 / 98304 and prompt sits near 6600 t/s — context is free in that range. At 131072 it collapses to 87.0 t/s and 3728 t/s prompt, for **176 MiB** less free VRAM (701 → 525), and 163840 refuses to load. The cliff is reproducible but its **cause is not established**, and the obvious explanation is already dead: "the Windows driver spills to shared memory once VRAM is nearly full" was tested against gemma-4-31B on 2026-08-05 and fails — that model runs 77.3 / 78.2 / 78.1 t/s at 577 / 1540 / 2508 MiB free, i.e. flat, with no CPU offload, at a margin *tighter* than the 701 MiB where Ornith is still fine. So free VRAM alone does not predict it; something about this model's allocation at 131072 does, and nobody has looked with a driver counter. The counter-intuitive consequence: with `fit = on` llama.cpp silently pushes MoE experts to CPU (`tensor overrides to CPU are used with mmap enabled`) and reaches 110.9 t/s at 131072 — *faster* than `fit = off` at the same ctx (87.0), because dodging the cliff beats falling off it. But both lose badly to simply staying below it, so the skill's rule "shrink ctx rather than offload experts" survives, while its unstated assumption "full GPU residency is always fastest" does not. Chosen `ctx-size = 65536` (1111–1137 MiB free, 153.0–157.9 t/s across two runs) over 98304, which measured equally fast (157.4 t/s) but is the *last* known-good point before the collapse; 65536 is one 32k step below it and was measured twice. That is the whole argument — the original "leaves only 701 MiB free" reasoning does not survive the gemma-4-31B result above. `fit = off` is **load-bearing here, not cosmetic** as it is on Qwen3.6-27B: without it this section silently runs the slow offloaded configuration. Two things the server itself reported and that are **not** acted on: `chat template supports preserving reasoning, consider enabling it via --reasoning-preserve` — the card documents `reasoning_content` but never says thinking should be carried across turns, and Qwen 3.5, which this is post-trained on, says the opposite, so the skill's "do not set what the card does not confirm" applies. The suspicion that **gemma-4-31B sits in this same cliff was tested and is false** — see its own bullet above; its 65536 stays.
