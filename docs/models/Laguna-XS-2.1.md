# Laguna-XS-2.1
> Extracted verbatim from AGENTS.md on 2026-08-15. "Above/below" references may point
> to sibling files in this directory or back to AGENTS.md.

Laguna XS 2.1 (poolside, OpenMDW-1.1, agentic coding): 33B-A3B MoE (arch `laguna`, 40 layers, 256 experts + 1 shared, native 262k ctx). Mixed attention layout — 10 global-attention layers + 30 sliding-window (512) layers in a 3:1 ratio with sigmoid gating and per-layer rotary scales — so only a quarter of the layers carry a growing KV-cache and long contexts stay cheap on VRAM. Built for long-horizon agent work (SWE-bench Verified 70.9, SWE-bench Multilingual 63.1, Terminal-Bench 2.0 37.5). Reasoning is interleaved between tool calls, and the model expects *preserved thinking* (prior assistant `reasoning_content` kept in the message history) → `jinja = true` + `reasoning-format = auto`, and clients that drop thinking blocks will see it stop reasoning in follow-up steps. **Thinking is not on by default in this GGUF**, contrary to what the card implies: the embedded template opens with `{%- set enable_thinking = enable_thinking | default(false) -%}` (verified 2026-08-04 by reading the template out of the GGUF metadata — note it sits past the 100 MB mark, a `strings` window of a few MB misses it entirely). Only under `enable_thinking` does the template render `<think>` + `reasoning_content` + `</think>` for *every* history message, which is exactly the preserved thinking the agent loop needs; the else branch emits a bare `</think>`. hermine's preset therefore sets `reasoning = on` explicitly rather than trusting `--reasoning auto` to flip it. Whether `auto` would have flipped it anyway is **unverified** — the template default is the measured fact, the behaviour of `auto` against this template is not. If a rendered prompt ever shows thinking still off, `chat-template-kwargs = {"enable_thinking": true}` sets the template variable directly. Whether the template declares `supports_preserve_reasoning` (what `--reasoning-preserve` looks for) is also unverified: the string is absent from a `strings` dump, but that dump was not a structured metadata read. Upstream llama.cpp support merged via PR #25165 (2026-07-22). Preset uses bartowski's imatrix `IQ4_XS` (18.2 GB) for KV/compute headroom on a 24 GB card. hermine runs `ctx-size = 163840` with KV `q8_0`/`q8_0` — **measured** with `llama-fit-params` 2026-08-04: model 17259 + KV 3463 + compute 837 = 21559 MiB of 23027 (~1468 free). The neighbouring points were measured too: 131072 → 20719 (2308 free), 196608 → 22399 (628 free), 262144 → 24079, which does **not** fit. 163840 was chosen over 196608 because 628 MiB is as thin as the gemma-4-31B section that this file already flags as a low-margin gamble. Unlike the Qwen sections these figures are complete rather than a lower bound, because Laguna has no MTP drafter and `ngram-mod` needs no context of its own. The previous `ctx-size = 32768` was pure caution and cost a factor of five. Its KV pair was also the mixed `q8_0`/`q4_0` that collapses throughput on this CUDA box (see the note further down), so both were wrong at once. Vendor sampling (the only preset the card documents, used for all published benchmarks): `temp 1.0`, `top-p 1.0`, `top-k 20`. A DFlash speculator exists (`poolside/Laguna-XS-2.1-DFlash`) and the build advertises `--spec-type draft-dflash`, but no GGUF in llama.cpp's own `dflash` arch was found — so no *draft-model* speculator is wired. It does run `spec-type = ngram-mod`, which needs no draft model at all, making that the only speculator this model can currently use.
