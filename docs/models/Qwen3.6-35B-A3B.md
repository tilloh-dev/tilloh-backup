# Qwen3.6-35B-A3B
> Extracted verbatim from AGENTS.md on 2026-08-15. "Above/below" references may point
> to sibling files in this directory or back to AGENTS.md.

Qwen3.6-35B-A3B (unsloth `-MTP-` build, `UD-IQ4_XS`, 18.2 GB on disk): 35B-A3B MoE (arch `qwen3_5_moe`, 40 layers, 256 experts + 1 shared, 8 routed active, native 262k ctx). Hybrid layout `10 × (3 × Gated-DeltaNet → MoE → 1 × Gated-Attention → MoE)` means only 10 of 40 layers carry a growing KV-cache (2 KV heads, head dim 256), which is why 262k ctx is affordable at `q8_0`. MTP ships inside the GGUF, so `spec-type = draft-mtp,ngram-mod` needs no `model-draft`. **Measured** on hermine with `llama-fit-params` 2026-08-04 at `ctx-size = 262144` + `q8_0`/`q8_0` + `flash-attn on`: model 16435 + KV 2782 + compute 820 = **20037 MiB of 23027** (~2990 MiB free), plus 515 MiB model / 264 MiB compute on the host. That figure **excludes the MTP context** — `llama-fit-params` rejects `--spec-type`, so the real peak is higher and remains unmeasured; the ~2.9 GiB headroom is the reason 262144 is kept anyway. `cache-type-k/v-draft = q4_0` is set, but note it was added on the assumption that it saves VRAM, and the gemma-4-31B measurement below disproves that for MTP drafters generally — it is kept because it is free, not because it was measured to help here. Sampling: the card gives three **whole** sets and they are not to be mixed — thinking/general `temp 1.0` + `presence-penalty 1.5`, thinking/precise-coding `temp 0.6` + `presence-penalty 0.0`, instruct `temp 0.7` + `presence-penalty 1.5` (all three share `top-p` 0.95/0.95/0.80, `top-k 20`, `min-p 0.0`). The presets use the coding set whole. Pulling only the `1.5` into it would be a combination the vendor never publishes, and it is wrong on the merits: a presence penalty punishes repeated tokens, which is precisely what code consists of, and the card warns that higher values can cause language mixing. The one place the two models differ is the *general* set — 35B uses `presence-penalty 1.5` there, 27B uses `0.0` — so that difference is invisible as long as both run the coding set. The presets use the coding set — before this change both `models.ini` and `models.example.ini` set **no sampling at all** for this model and silently ran llama.cpp's defaults (`temp 0.8` / `top-p 0.9` / `top-k 40`), which contradicts the card. It is also a VLM, but no `mmproj-*.gguf` is present in the model directory, so the presets are text-only.
