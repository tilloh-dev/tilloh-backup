## Model-ID case sensitivity

**The model ID is the `models.ini` section name, case-sensitive, and two entries were dead because of it.** `opencode.jsonc` carried `ornith-1.0-9b` / `ornith-1.0-35b` while the router serves `Ornith-1.0-9B` / `Ornith-1.0-35B`; a request with the lowercase form returns `400 model 'ornith-1.0-9b' not found`, so neither was ever selectable. Verified 2026-08-10 by diffing the whitelist against `/v1/models` and then issuing the failing request. Both are corrected. When adding a model, take the ID from `/v1/models` rather than from the `alias` key — `alias` is often the bare filename (`gemma-4-31B-it-qat-UD-Q4_K_XL.gguf`) and is *not* what clients send. `/v1/models` also lists one entry that is not ours, `unsloth/gemma-4-E4B-it-GGUF:Q4_K_XL`, from llama.cpp's own HF cache.

## Image-capability declarations

**`gemma-4-26B-A4B` and `gemma-4-31B` are declared image-capable in `opencode.jsonc` but are not.** Neither preset section sets an `mmproj` key, and the only mmproj on hermine is Muse-Glimmer's (verified 2026-08-10 — a search for `*mmproj*`/`*clip*` across the models tree returns exactly one file). So `Muse-Glimmer-30B` is currently the only genuinely multimodal entry, and its `"input": ["text", "image"]` is correct while the two gemma ones will fail the moment someone pastes an image. Left as-is deliberately: the fix is either downloading the two mmproj files or narrowing the declaration, and that is a capability decision rather than a typo.

[Update 2026-08-15: `Qwen3.8-27B` now also ships a wired mmproj, so "only genuinely multimodal entry" no longer holds — it is Muse-Glimmer plus Qwen3.8.]

## Bash guard (command-guard.js)

Bash guard: **no longer shipped from this repo.** The merged `command-guard.js` lives in `stadtwerk_ai_config/.opencode/plugin/`; that repo's `install-opencode.sh` drops it into the same `~/.config/opencode/plugin/`, so it applies in every project. It hooks `tool.execute.before`, **normalises** each command (strips `env`/`sudo`/`nice`/`timeout` wrappers, resolves absolute paths & `$(which x)` to bare verbs, strips `.exe`, decodes base64 as UTF-8 *and* UTF-16LE for PowerShell's `-EncodedCommand`, reads here-docs, re-scans `-c`/`-Command` payloads of sh/python/node/powershell/cmd) and **recursively splits** it across pipes/`&&`/`;`/subshells before matching — which is what closes the string-glob bypasses the wren.wtf "Stop Using OpenCode" post calls out. Rules are **embedded in the `.js`** (an external rule file would not survive: the team installer copies `plugin/*.js` only, and a missing rule file used to disable guarding silently) and are **deny-only**. The ask tier belongs to the team config, because a plugin cannot prompt: the `permission.ask` hook is declared in `@opencode-ai/plugin` 1.14.20's types but has **zero dispatch sites** in the opencode 1.18.12 binary (verified by enumerating every `trigger("…")` literal). Blocked: recursive delete of `/`~/`$HOME`/system paths, filesystem/partitioning tools, raw device writes, download-piped-to-shell, private-key reads, fork-bombs, shell redirection into CI workflows / `clusters/**` / Terraform, and destructive kubectl/helm **against prod** — the context comes from an explicit `--context` flag if present (otherwise `kubectl --context prod delete` would bypass it while test is active), else from `kubectl config current-context`, resolved lazily so reads stay fast. Fail-closed twice: destructive + undeterminable context, and base64-for-a-shell that will not decode. Health signal: the toast **"Löschschutz aktiv"** at startup plus `echo guard-selftest`, which must be blocked — a plugin that fails to load cannot warn about itself, so only a positive signal makes its absence detectable. Verified 2026-08-04: 33/33 unit cases, and 0 false positives across 2253 distinct real commands from this machine's log — **but the zero no longer holds**: on 2026-08-10 `rm -f /tmp/opencode/a.json /tmp/opencode/b.json /tmp/opencode/c.json` tripped `rm-rf-dangerous-target`, with no `-r`, no glob and three explicit paths under `/tmp`. Splitting it into three single-target `rm -f` calls passed. So the rule appears to key on argument count or the plain `rm -f` verb rather than on a dangerous target, which is a false positive in the literal sense the rule name claims to exclude. Not a sandbox — it cannot see inside a shell script it invokes, and writing *about* its rules in a here-doc can trip them.

## Permissions (team baseline)

Permissions come from the **team** config `~/.config/opencode/opencode.json` (installed by `stadtwerk_ai_config`), *not* from the personal `opencode.jsonc` — a `permission` block there would override the team baseline, which that installer explicitly forbids. The baseline is default-**ask** (`bash: {"*": "ask"}`) with an allow-list of ~116 read-only patterns, `edit: allow` except CI workflows / `clusters/**` / Terraform, and a `read` deny-list covering `.env*`, `.ssh/**`, `*.pem`, `.aws/credentials` and kubeconfigs. Measured 2026-08-04 against 6758 logged bash calls from this machine: 34.6 % would prompt (62.6 % before the allow-list was widened by 14 patterns, `echo *` alone accounting for 1547 calls).
