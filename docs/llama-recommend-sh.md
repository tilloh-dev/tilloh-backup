# recommend.sh — rewrite history (2026-08-04)
> Extracted verbatim from AGENTS.md on 2026-08-15. "Above/below" references may point
> to sibling files in this directory or back to AGENTS.md.

Skill `.opencode/skills/llama-preset/` (`scripts/recommend.sh`) — **moved out of `.claude/skills/` on 2026-08-04 and substantially rewritten.** It generates/updates a `presets/models.ini` `[section]` from measured hardware (`llama-server --list-devices`, `llama-fit-params`, iGPU deprioritized) plus agentic defaults. What changed and why, because each item was a real defect found by testing it against this machine rather than reading it:

- It was **invisible to OpenCode**: its `description` was 1371 characters against a documented 1024 limit, so it never appeared in `<available_skills>` while `commit-push` in the same directory did. Now 984. Every session before this one ran without it, which is the likeliest reason the presets had drifted so far.
- `cache-type-v = q4_0` was a global "floor". On CUDA that is the mixed pair that collapses throughput 9× (see the note above), and the skill would have regenerated it. The V type is now **backend-derived** from the device id: `q4_0` on Vulkan, matched to K everywhere else.
- `spec-type` knew only `draft-mtp` from a hardcoded list. Both the allowed KV types and the speculator list are now **parsed out of `--help`**, so a newer llama.cpp unlocks better defaults with no edit — the point of keeping this box's server current. `ngram-mod` is chained in whenever the build offers it.
- Nothing inspected the **embedded chat template**, so Laguna's `enable_thinking | default(false)` was invisible. The script now scans it (200 MiB window — the template sits past the tensor-name table) and reports thinking/preserved-reasoning findings instead of silently accepting the card's claim.
- It could not run on hermine at all: `resolve_bin` matched only `llama-server`, and sourcing the CRLF `config.env.example` broke bash. Worse, passing a `/mnt/c/...` path to the Windows `.exe` makes `llama-fit-params` print its header and **no data line** — a silent failure the script read as "does not fit" and turned into `ctx-size = 4096` for a model that measurably does ~160k. Paths are now converted via `wslpath -m`, config precedence is env > `config.env` > `config.ps1` > `.example`, and CR is stripped.
- Section names were derived from the GGUF filename (`[Laguna-XS-2.1-IQ4_XS.gguf]`) rather than the bare alias, so every existing model looked new. Combined with a CRLF-blind `$0==sec` match in the merge, `--write` would have appended a **duplicate** section.
- `--write` **deleted keys it does not manage.** Sampling, `reasoning` and `cache-ram` showed up in the diff as "no longer set" and would have been dropped. They are now carried over verbatim and reported as `= key (kept)`. The merge also replaces in place instead of moving the section to the end of the file, because section order is maintained by hand.
- `n-cpu-moe` is now **opt-in** (`--allow-cpu-moe`). It used to buy native context by pushing experts to host RAM, which puts a PCIe round trip in the generation path — the wrong trade for long agent sessions. Default is to shrink `ctx-size` until everything is GPU-resident.
- Sampling guidance changed from "prefer the lower temperature" to "adopt one published set whole, never mix values across sets", which is the rule that keeps a general-set `presence-penalty 1.5` out of a coding preset.
- A sibling `mtp-*.gguf` counted as a name match, so the moment a model *had* its drafter on disk it became unreachable by alias: `recommend.sh gemma-4-26B-A4B` died with "Ambiguous model", and `gemma-4-31B` had the same defect all along. Drafters are now excluded from target resolution unless asked for by exact filename — the script looks for them a few steps later anyway.
- The drafter exclusion above was too narrow: it matched only `mtp-*.gguf`, so `Ternary-Bonsai-27B-dspark-Q4_1.gguf` made `Ternary-Bonsai-27B` ambiguous in exactly the same way. Resolution now skips any sibling whose name contains `mtp`, `dspark`, `dflash`, `eagle` or `mmproj` — the draft-* families this build's `--spec-type` lists, plus vision projectors. Naming is vendor convention rather than a standard, so this is a heuristic, and asking for such a file by its exact name still bypasses the filter.
- `presets/models.example.ini` contained a **duplicate** `[gemma-4-26B-A4B]`, byte-identical, at two positions. Removed the earlier one so the remaining position matches `models.ini`'s hand-maintained order (both files now list the same sections in the same sequence). This is the failure mode the CRLF-blind section match used to produce, so it is worth re-checking after any `--write`.

Validation: run against `Laguna-XS-2.1` on hermine it independently produced `ctx-size = 159744` versus the 163840 chosen by hand — one 4096 step apart, from an independent path. Still not automated: reading the model card, weighing the VRAM margin, and deciding on the template finding. `temp = 0` remains refused without `--zero-temp-ok`; OCR models (section name matches "ocr") keep conservative defaults; vendor keys arrive via `--extra KEY=VALUE` and never override a hardware/agentic-owned key.
